# Refleksi: Framework dan Dynamic Dispatch

Framework yang ditulis bertahun-tahun lalu hanya mengenal kontrak, bukan kelas yang saya tulis hari ini. Framework mendeklarasikan kelas abstrak atau antarmuka, misalnya method `handle()`, lalu menyimpan objek milik pemakai dalam variabel bertipe kontrak itu (upcasting). Saat berjalan, framework memanggil `handle()` pada variabel tersebut. Karena dynamic dispatch, bahasa tidak memakai tipe variabel, melainkan memeriksa kelas objek yang sebenarnya, lalu menjalankan method milik kelas saya. Itu sebabnya framework tidak perlu dikompilasi ulang dan tidak butuh rantai `instanceof` untuk mengenali kelas baru: ia cukup mempercayai kontrak. Kode saya baru tersambung ke framework saat program berjalan, ketika objek saya didaftarkan. Contohnya `kirimSemua()` pada `notifikasi.php`, yang tetap bisa memanggil saluran Telegram yang ditulis belakangan. Penulis framework dan penulis aplikasi bekerja terpisah; satu-satunya kesepakatan mereka adalah kontrak itu. Kelas yang melanggar kontrak, misalnya lupa mengimplementasikan method abstrak, langsung ditolak saat kompilasi. Hasilnya adalah prinsip Open-Closed: framework tertutup untuk diubah, tetapi terbuka untuk diperluas.
