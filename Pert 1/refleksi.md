# Refleksi Pertemuan 1: Data yang Tercerai-berai

Pada semester lalu saya membuat program rekap nilai untuk tugas mata kuliah Algoritma dan Pemrograman. Data mahasiswa saya simpan dalam tiga array terpisah: satu untuk nama, satu untuk NIM, dan satu untuk nilai akhir. Awalnya program ini terasa sederhana, tetapi masalah muncul ketika dosen meminta tambahan kolom kehadiran dan fitur mengurutkan mahasiswa berdasarkan nilai. Saat saya mengurutkan array nilai, array nama dan NIM tidak ikut bergeser, sehingga nilai milik satu mahasiswa tertukar dengan nama mahasiswa lain. Saya harus menulis ulang setiap potongan kode yang menyentuh ketiga array, dan beberapa kali lupa menyamakan indeksnya. Menambah satu kolom baru berarti mengubah banyak tempat sekaligus, dan satu kesalahan kecil membuat seluruh rekap salah tanpa ada pesan galat apa pun.

Dengan objek, masalah ini bisa dihindari. Setiap mahasiswa menjadi satu objek `Mahasiswa` yang membawa nama, NIM, nilai, dan kehadiran dalam satu paket. Mengurutkan berarti memindahkan objeknya, sehingga data milik satu orang tidak mungkin terpisah dari orangnya. Aturan seperti "nilai harus 0 sampai 100" juga bisa ditulis sekali di dalam kelas, bukan tersebar di banyak tempat. Menambah kolom kehadiran cukup dilakukan di satu kelas, dan kode lain tidak perlu tahu cara data itu disimpan. Dari sini saya memahami bahwa objek bukan sekadar cara menulis kode yang berbeda, tetapi cara menjaga data dan perilakunya tetap bersama sehingga program lebih mudah diubah dan lebih sulit rusak.
